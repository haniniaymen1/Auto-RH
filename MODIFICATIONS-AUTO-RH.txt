VERSION 0.2.209 — Démarrage, administration et gestion des ports (Win + Linux)
================================================================================
Objet : système de gestion du démarrage multiplateforme, création automatique
du superadministrateur et gestion dynamique des ports par le fichier .env.

1. GESTION UNIFIÉE (NOUVEAU)
----------------------------
  - gestion.sh (Linux/macOS) et GESTION.bat → gestion.ps1 (Windows) :
    un point d'entrée unique — demarrer / demarrer-silencieux (arrière-plan
    détaché) / arreter / redemarrer / etat / journaux / ports / superadmin /
    installer / aide. Les PORTS sont lus dans le .env (aucun port codé en
    dur ; défauts 4000/4001 uniquement si le .env est absent).

2. VÉRIFICATEUR DE PORTS (NOUVEAU : scripts/verifier-ports.js)
--------------------------------------------------------------
  Lit le .env (PAIESAGE_PORT_ADMIN > PORT > 4000 ; PAIESAGE_PORT_PORTAIL >
  PORTAL_PORT > 4001), contrôle la disponibilité AVANT lancement, identifie
  le propriétaire du port (PIDs enregistrés logs/paiesage-processus.json +
  ligne de commande, via netstat/Windows, ss, lsof ou /proc/net/tcp) et
  affiche l'état HTTP. Modes : verifier [port ciblé] / etat / liste.
  Codes : 0 libre (ou à nous) ; 1 conflit AUTRE programme ; 2 déjà en cours.
  RIEN n'est jamais tué en cas de conflit : message + PID + remédiation.

3. LANCEURS — PORTS ET VÉRIFICATION (MODIFIÉS)
----------------------------------------------
  Linux : DEMARRER-LINUX-MAC.sh, DEMARRER-PORTAIL-LINUX-MAC.sh,
          DEMARRER-TOUT-LINUX-MAC.sh, INSTALLER-ET-DEMARRER-LINUX-MAC.sh
  Windows : DEMARRER-WINDOWS.bat, DEMARRER-PORTAIL-WINDOWS.bat,
            DEMARRER-TOUT-WINDOWS.bat
  - PORT / PORTAL_PORT lus du .env ; lignes ÉCRITES dans le .env si absentes
    (idempotent, valeur utilisateur JAMAIS écrasée) — défauts alignés sur
    4000/4001 partout (moteur, lanceurs, vérificateur, documentation) ;
  - vérification de disponibilité AVANT lancement (échec rapide et clair) ;
  - DEMARRER-TOUT-WINDOWS.bat : création automatique du superadmin ajoutée
    (identique à Linux), écriture idempotente des ports, contrôle des deux
    ports avant l'ouverture des fenêtres ;
  - diagnostic du lanceur TOUT Linux : l'appartenance d'un port se juge par
    les PIDs ENREGISTRÉS et la ligne de commande (start-prod.js /
    standalone/server.js / portail-server.js / next-server) — un « node »
    étranger lancé dans le dossier n'est plus confondu avec l'application ;
  - scripts/start-prod.js : le .env est chargé AVANT l'application du défaut
    PORT (correctif : une ligne PORT du .env était ignorée en démarrage
    direct) ; défaut 3000 → 4000 ;
  - portail-server.js : défaut 4001 confirmé, commentaire aligné.

4. SUPERADMINISTRATEUR AUTOMATIQUE (MODIFIÉ : scripts/creer-superadmin.js)
-------------------------------------------------------------------------
  Mode --assurer appelé par TOUS les lanceurs (Linux et Windows) au premier
  démarrage sur base vierge :
  - auto-suffisant : crée la base (prisma db push) et le .env (DATABASE_URL)
    s'ils manquent, et fournit un DATABASE_URL par défaut — il fonctionne
    même appelé sans lanceur (gestion.sh superadmin, cron) ;
  - honore LUI-MÊME la politique SUPERADMIN_AUTO=0 (double protection avec
    les lanceurs) ;
  - idempotent : rien n'est créé si un compte SUPERADMIN actif existe
    (anti-doublon) ; identité configurable par SUPERADMIN_EMAIL /
    SUPERADMIN_PASSWORD dans le .env, sinon mot de passe aléatoire affiché
    une fois et consigné dans logs/compte-superadmin-initial.txt.

5. DOCUMENTATION (MODIFIÉE)
---------------------------
  .env.example (section PORTS — source unique de vérité + SUPERADMIN_AUTO),
  GUIDE-INSTALLATION-LINUX-WINDOWS.txt et README-DEPLOIEMENT-LOCAL.md
  (défauts 4000/4001, Gestion unifiée), package.json (version 0.2.209).

6. VALIDATION (batterie scripts/test_v0209_ports.sh — LINUX, 37 contrôles)
--------------------------------------------------------------------------
  T1 premier démarrage base vierge : défauts 4000/4001 écrits dans le .env,
     superadmin créé, les deux interfaces répondent ;
  T2 relance : interfaces conservées (GARDE), toujours 1 seul superadmin ;

  T5 démarrage direct start-prod.js : ligne PORT du .env honorée ;
  T6 identité superadmin par .env (connexion API → 200, mot de passe non
     consigné) et SUPERADMIN_AUTO=0 (aucune création) ;
  T7 cycle gestion.sh : demarrer-silencieux / etat / journaux / redemarrer
     (nouveaux PIDs) / ports / arreter (ports libérés).
  Windows : mêmes mécanismes (lecture .env findstr, verifier-ports.js
